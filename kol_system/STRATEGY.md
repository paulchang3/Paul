## 第一部分：你的專長稀缺性與亮點盤點

### 1.1 稀缺性來自「組合」，不是單項

醫材法規圈的人才供給結構大致是這樣：

| 人才類型 | 市場上數量 | 缺口 |
| --- | --- | --- |
| 單一市場 RA 專員／主管（只熟 FDA 或只熟 TFDA） | 很多 | 跨國視角 |
| 大型顧問公司的跨國團隊 | 有，但貴、慢、團隊制 | 個人化、彈性、決策者直接對話 |
| 個人顧問、懂 2–3 個市場 | 少數 | 五大市場全覆蓋的實戰 |
| **五大市場（FDA / EU MDR / TFDA / NMPA / PMDA）× 跨國協調實戰 × 商業化語言** | **極少** | ← 你的位置 |

你的稀缺性是三環交集：

```
        法規深度（五大市場）
              /\
             /  \
            /稀缺\
           /  區  \
  跨國協調實戰 ──── 商業化思維
 （多國同步送件）  （用時程與資本效率說話）
```

外加一個放大器：**中英雙語與跨文化溝通**——美系直接務實、日系謹慎有禮、中國市場重關係，你能在同一個案子裡切換這三種溝通模式，這是歐美顧問和單一市場顧問都做不到的。

### 1.2 亮點盤點：把稀缺性「證據化」

稀缺性只有被看見、可查證，才會變成商業價值。你的亮點必須全部轉成**可重複引用的證據資產**：

| 亮點 | 證據化形式 | 系統對應 |
| --- | --- | --- |
| 上市時程縮短 30–50% | 一頁式方法論說明 + 匿名案例數字 | Drive「分享素材」資料夾 |
| 歐美同步送件 18 個月 → 11 個月 | 匿名案例摘要（情境—做法—成果） | 內容行事曆「案例拆解」支柱 |
| 一次試驗、多國採用的臨床協調 | 趨勢深度文章 | 內容行事曆「趨勢觀察」支柱 |
| 五大市場審查邏輯差異 | 多國註冊時程比較表、法規動態季報 | 季報範本自動生成 + 電子報寄送 |
| 方法論本身 | 命名為「統一送件策略框架」，讓它可被轉述 | 洞察頁 / 簡報素材 |

**關鍵原則：把方法論命名化。**「統一送件策略框架」這六個字，比十頁簡報更容易被 KOL 在他們的內部會議裡轉述——被轉述，就是最高級的曝光。

### 1.3 一句話定位（依受眾切換）

- **通用**：我協助醫材公司把「多國個別註冊」重組為「一次策略、多國同步」，平均縮短上市時程 30–50%。
- **對臨床 KOL**：一次到位、多國適用的臨床試驗方案，減少重複驗證。
- **對高管／投資人**：把上市時程轉化為市場先機與資本效率。
- **對同行**：跨國協調網絡與案源互補。

## 第二部分：被動曝光策略（Inbound——讓對的人自己找到你）

### 2.1 原理

被動曝光的目標只有一個：**在你主動接觸之前，KOL 已經透過內容認識並信任你。**

三個機制在運作：

1. **信任前置**：冷接觸的回覆率取決於對方點開你 LinkedIn 之後看到什麼。持續發布的專業內容 = 自動運轉的信任背書。
2. **內容複利**：一篇「MDR 過渡期解讀」發布後會持續被搜到、被轉發，邊際成本為零。
3. **盡職調查效應**：決策者在答應見面前一定會搜尋你。公開洞察頁 + 內容存檔，就是為這次搜尋準備的。

### 2.2 四大內容支柱

| 支柱 | 頻率 | 主要管道 | 目的 | 系統支援 |
| --- | --- | --- | --- | --- |
| 法規動態解讀 | 每週 1 則短貼文 | LinkedIn | 維持存在感、展示即時性 | **每週情報彙整信自動送素材** |
| 案例拆解 | 每月 1 篇 | LinkedIn + 洞察頁 | 證明方法論有效 | 內容行事曆排程 |
| 趨勢觀察 | 每季 1 篇深度文 | 洞察頁 + 投稿 | 建立思想領導地位 | 內容行事曆排程 |
| 法規動態季報 | 每季 1 期 | Email 電子報 | 系統化觸達 A/B 級名單 | **季報文件自動生成 + 電子報自動寄送** |

### 2.3 管道優先序

1. **LinkedIn**（第一優先）：你的 KOL 都在這裡。注意：LinkedIn 官方 API 不開放個人自動發文，系統的做法是「每週把整理好的素材寄到你信箱，你花 15 分鐘改寫貼出」——半自動，但合規。
2. **Email 季報**（第二優先）：唯一完全可程式化的管道。系統直接對「訂閱電子報 = Y」的 A/B 級 KOL 逐一個人化寄送，並自動寫回接觸紀錄。
3. **公開洞察頁**（第三優先）：Web App 自動發布你的已發布內容清單，取代 Google Sites（Apps Script 無法自動排版 Sites，這是誠實的技術限制）。這一頁就是「盡職調查效應」的落點。
4. **產業媒體投稿**（RAPS Regulatory Focus、MedTech Dive）：低頻但權威背書。
5. **演講／Panel**：由前四項曝光自然帶來邀約。

### 2.4 被動曝光最大的敵人是「內容生產成本」——系統怎麼解

- **素材自動送上門**：系統每週一早上抓取你設定的 RSS 情報源（FDA、產業媒體等），彙整成一封分市場的摘要信。你的工作從「找素材 2 小時」變成「挑一則寫觀點 15 分鐘」。
- **管線化**：內容行事曆分「構想 → 草稿 → 已發布」三態，儀表板顯示管線存量，構想枯竭時一眼看見。
- **一魚多吃**：季報的每一節，拆出來就是 4–6 則 LinkedIn 貼文；系統的內容行事曆讓你把同一素材登記到多個管道。
- **曝光回收成名單**：洞察頁附訂閱入口，新訂閱者進入 KOL 名單時標記「曝光來源 = 內容訂閱」——這是被動曝光的轉化閉環。

### 2.5 被動曝光 KPI

每月發布數（目標 ≥ 5）、電子報訂閱數、洞察頁被動詢問數、「曝光來源 = 內容訂閱」的新名單數。

## 第三部分：主動曝光策略（Outbound——你去找對的人）

### 3.1 分級 × 節奏

主動曝光的成敗不在話術，在**節奏的紀律**。人腦記不住 30 個人的跟進時點，系統可以：

| 等級 | 定位 | 預設接觸週期 | 降溫警示門檻 |
| --- | --- | --- | --- |
| A 級（核心合作） | 有決策權、有實際跨國需求 | 每 14 天 | 超過 30 天未接觸 |
| B 級（關係培養） | 有影響力、決策鏈長 | 每 30 天 | 超過 60 天未接觸 |
| C 級（曝光轉介） | 擴大聲量、轉介 | 每 90 天（以季報維繫為主） | 超過 120 天未接觸 |

前期節奏仍依 §5.1 手冊：接觸後 2 天內補資料 → 第 2 週分享新聞 → 第 4–6 週請教問題 → 第 8–10 週測試合作意願。

### 3.2 「鉤子式跟進」優於「排程式跟進」

最好的跟進不是「好久不見」，而是「上次你提到 X，我看到這個想到你」。所以系統把每次接觸紀錄的「下一步」欄位**自動寫入 KOL 的「下次跟進鉤子」**，並依等級自動推算下次跟進日。你每天早上收到的摘要信裡，每個人名旁邊都帶著現成的鉤子。

### 3.3 系統支援的主動曝光動作

1. **每日 08:00 跟進摘要信**：今日到期 + 已逾期 + 關係降溫警示，附鉤子，直接從信箱開工。
2. **一鍵產生開發信草稿**：依對象選擇話術（保守型／價值導向型／高階型／三種跟進範本），系統代入姓名、公司、鉤子後直接建立 Gmail 草稿——你只做最後 20% 的個人化，永不空白頁起步。
3. **Calendar 同步**：未來 60 天的跟進日自動建立全天事件，跟進提醒出現在你每天看的行事曆裡。
4. **接觸自動回寫**：電子報寄送、接觸紀錄都自動更新「最近接觸日」，降溫警示因此永遠準確。

### 3.4 主動曝光 KPI

每週新接觸數（目標 5–10）、回覆率（>15% 健康）、對話→會議轉換、會議→小規模試點轉換、逾期跟進數（目標 0）。

## 第四部分：雙軌飛輪——被動與主動如何互相放大

```
   主動接觸（開發信/會議）
        │  「要不要順便訂閱我的季報？」
        ▼
   內容訂閱（進入電子報名單）
        │  每季自動觸達，零成本維持溫度
        ▼
   被動曝光（季報/貼文/洞察頁）
        │  對方回信、按讚、提問 = 新鉤子
        ▼
   鉤子觸發下一次主動接觸  ──►  回到頂端
```

- 主動接觸的**收尾動作永遠是導入被動管道**（訂閱季報），讓關係維持不再依賴你的記憶力。
- 被動內容產生的每一次互動，都是下一次主動接觸的**合法理由（鉤子）**。
- 冷名單（C 級、已讀不回者）丟進電子報名單低成本養著，系統會在他們互動時給你信號。

## 第六部分：誠實的限制

1. **LinkedIn 無法自動發文**：LinkedIn API 不開放個人帳號自動發文。系統做到「素材自動彙整 + 內容排程提醒」，發文最後一步必須是你。
2. **Google Sites 無法程式化排版**：以 Web App 洞察頁取代，效果等價且全自動。
3. **Gmail 寄送額度**：一般帳號每日約 100 封、Workspace 約 1,500 封。系統寄送前會檢查剩餘額度；名單超過額度時分批寄送。
4. **RSS 情報源品質**：預設種子只有產業媒體；官方法規來源（FDA/TFDA/NMPA/PMDA）的 RSS 網址請在「情報來源」分頁自行確認補上，系統對失效來源會自動略過並在信中註記。
